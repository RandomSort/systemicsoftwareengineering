## Core argument (inferred)

Roughly half of the author's 2017–2018 speaking is one sustained project:
getting ordinary developers to genuinely understand their version control
system instead of ritually operating it. The titles trace the pedagogy:
answer the motivation objection ("I'm just a developer, why should I learn
Git?"), demystify the expert layer ("Jedi Mind Tricks"), teach through
simulation rather than prescription ("A Simulated Git Workflow"), and
democratize practices ("for the rest of us"). The implied theory of learning:
tool competence comes from an accurate *mental model* of the underlying
system, and workflows should be understood — even simulated — before being
adopted. (This thread later culminated in the author's book *Practical Git*,
Apress 2020 — outside this corpus.)

## Extracted claims

- **[normative]** (inferred) Version-control fluency is core developer
  competence, not a specialist's or "the build person's" concern — including
  in embedded software organizations.
- **[empirical]** (inferred, speculative) Developers who operate Git by
  memorized ritual rather than model are a widespread population — large
  enough to build a multi-year talk circuit on.
- **[normative]** (inferred from "A Simulated Git Workflow") Workflows should
  be evaluated by simulating their dynamics, not adopted by branding
  (git-flow, trunk-based) — a small systemic-modeling move applied to team
  process.

## Agreements and disagreements

- Feeds a candidate framework concept about *mental models as the unit of
  competence*: the same claim the framework repo makes about itself ("the
  product is thinking made explicit") applied to tool mastery.
- Tension to watch: "everyone must understand the tool deeply" pulls against
  the corpus's own rightsourcing/abstraction principle (DOPIER: not every team
  should own every layer). Where is the line between healthy abstraction and
  ritual ignorance? Neither piece answers it.

- Talk title as reusable framing: "I'm just a developer, why should I learn
  Git?" — the objection voiced verbatim, then answered.

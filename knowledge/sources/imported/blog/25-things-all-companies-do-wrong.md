# 25 things all companies do wrong

> **Evidence level:** talk page holds title, event (Aarhus DevOps Meetup), and
> meetup link only. Claims below are inferred from the title and the author's
> consulting context (Praqma-era, many client organizations); speculative
> until the list is recovered from the author or slides.

## Core argument (inferred)

A pattern catalogue: across many organizations, the same ~25 failure modes
recur — the word "all" claims these are systemic to how companies organize
software work, not local incompetence. This framing is itself a systemic
claim: if *every* company exhibits the same dysfunctions, the cause lives in
shared structures and incentives, not in individual companies' people.

## Extracted claims

- **[empirical]** (inferred, speculative) Organizational dysfunctions in
  software delivery are convergent — independent companies reinvent the same
  mistakes.
- **[definitional]** (inferred) "Doing it wrong" is assessable against some
  implicit reference model of healthy software delivery — the talk presupposes
  the kind of framework this repository is trying to make explicit.

## Agreements and disagreements

- The strongest corpus-internal argument *for* building a systemic framework:
  a consultant only accumulates a "25 things" list because the system, not the
  company, generates the failures. The framework should explain *why* the
  list is convergent, which the listicle format cannot.
- Counter-pressure: listicles of wrongness age badly and invite cargo-cult
  inversion ("stop doing these 25 things") — the framework should convert
  items into mechanisms, not prohibitions.
- Recovery task: the actual 25 items are the valuable payload and exist only
  with the author (or old slides). High-priority elicitation.

## Quotable

- Title itself: "25 things all companies do wrong" — note the load-bearing
  word is "all".

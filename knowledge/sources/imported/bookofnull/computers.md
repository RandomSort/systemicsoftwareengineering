# Computers

Source piece: `bookofnull/pieces/036-computers.md` (three-line piece using
brace expansion). Companion pieces: `017-agents.md`, `001-claude.md`.

## Core argument

"It {did, didn't} do / Exactly what I told it / That's the problem." The
brace expansion is the argument: whether the machine obeyed or not, the
problem is the same — the gap between what was said and what was meant.
Bugs are not machine disobedience; they are faithful execution of an
unfaithful specification of intent. The companion piece (017) extends this
to human-machine collaboration: humans and computers are complementary, but
"neither applies common sense" — composition does not close the gap, it
just moves the crack.

## Extracted claims

- **Definitional:** a bug is a mismatch between intent and instruction (or
  between mental model and machine model), not an error by the machine.
- **Empirical:** the classic failure mode ("the computer did exactly what I
  told it") persists unchanged across paradigms — from assembly to
  declarative config to LLM prompting, where instructions became natural
  language but the intent gap remained. (Checkable against the long lineage
  of this observation.)
- **Normative (017):** human-plus-machine systems should be designed for
  the shared blind spot — the place where neither party applies common
  sense — rather than assuming the human catches what the machine misses.

## Framework relevance

Seed for an intent-specification-gap concept: engineering as translation of
intent across representations, with each translation a place for meaning to
leak. Unusually current: it frames AI-assisted coding as the same old gap
with a friendlier syntax, connecting to the corpus's AI pieces (001, 041).
Links to language-precision pieces (005, 013, 031–033).
